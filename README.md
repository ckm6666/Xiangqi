# 中国象棋 · 本地 / 人机 / 联机对战（0.7.0）

参照 `Gomoku` 项目的技术栈与视觉风格开发的中国象棋桌面游戏：

- Python 3.10+ / PySide6 6.x（QtWidgets + QPainter 自绘棋盘）
- 宣纸、墨、朱砂、金与水漆的“古风”主题（QSS + 程序化绘制）
- 纯 Python 规则引擎，Qt 与客户端完全解耦，可供 AI/服务端复用
- 标准库 `unittest` 自动测试，PyInstaller 单文件打包

- **主菜单**：水墨山水背景 + 宣纸卡片 + 朱砂印章；模式按钮改为一列，
  「联机对战」为红色主按钮且位于首位，其下依次是「本地双人」「人机
  对战」「棋谱复盘」「残局挑战」与「退出游戏」。
- **对局页**：品牌标题、回合/将军/终局状态胶囊、红黑棋手卡片、木纹棋盘、
  手数、快捷键提示与底部操作按钮。
- **人机设置**：难度（入门/业余/高手/大师）与先手方（玩家先手/AI 先手）；
  切换先手方会重新开局，AI 思考期间两项设置暂时锁定。
- **联机大厅**：先输入服务器地址、昵称与密码登录或注册（在昵称/密码框
  按 Enter 也可直接登录）；昵称即登录账号。登录后顶部显示头像、昵称、

  「个人信息」窗口，可「自建房」邀请好友或进入排位队列，并可
  「退出登录」。离开自建房/排位对局后回到联机模式主页面，而不是
  主菜单。
- **个人信息**：窗口内展示大头像、昵称、称号、积分、战绩、胜率、
  最高连胜与成就；可选择 6 个内置头像或上传本地图片。查看他人资料时

  已是好友」按钮；查看自己时没有加好友按钮。
- **好友与排行榜**：大厅帐号下方有「好友」「排行榜」按钮。好友窗口管理

  玩家的称号与战绩，点击头像可打开该玩家的资料窗口。
- **好友私聊**：点击好友行的「聊天」打开私聊浮层，支持历史消息、实时

- **联机对局页**：显示双方昵称、在线状态、积分与称号；自建房等待阶段

## 动效与语音

- **走子动画**：本地、人机与联机共用同一套动画。棋子从起点略微提起，
  沿平滑曲线滑向终点（0.28 s），落子后才恢复棋盘交互；吃子时被吃棋子
  在终点淡出，不会出现“闪现”。人机模式下会等落子动画播放完毕再启动
  AI 搜索，避免搜索线程抢占 GIL 导致自己的落子动画来不及重绘。
- **中央特效**：`吃`（0.6 s）、`将军`（0.95 s）、`绝杀`（1.55 s）以
  宣纸光晕 + 书法字在棋盘中央弹出。若一手既吃子又将军，会先播“吃”再
  播“将军”；绝杀优先于普通将军。
- **中文语音**：使用 QtTextToSpeech 调用系统中文语音（Windows SAPI/
  WinRT，优先 Huihui/Yaoyao），播报“将军 / 吃 / 绝杀”。静音或音效音量
  为 0 时不播报；系统没有中文语音时静默降级。可通过环境变量
  `XIANGQI_DISABLE_VOICE=1` 关闭。
- **终局时序**：将死时先完成“绝杀”特效（以及可能排队的“吃”），再弹出
  结果窗口；认输/困毙没有绝杀特效时立即进入结果窗口。

## 称号、积分与个人资料

- **积分只来自排位赛**：排位匹配创建的房间按 Elo（K=32）计算，胜方加分、
  负方减分；普通房间只累计战绩，不影响积分。积分持久化在服务端 SQLite。
- **称号由积分决定**：棋童（<1200）、棋士（1200+）、上品棋士（1400+）、
  棋师（1600+）、大师（1800+）、特级大师（2000+）、棋圣（2200+）。
  对局终局弹窗会显示赛后加减分与称号变化，个人资料中显示距下一称号还差
  多少分。
- **战绩与胜率**：统计所有已完成联机对局（排位与普通房间）的胜/和/负与
  连胜；个人资料窗口实时展示。
- **成就**：由累计战绩与积分派生，例如初涉楚河、首战告捷、十战十胜、
  百局磨剑、三连胜、五连胜、登堂入室、国手风范。
- **头像**：内置 6 个程序化绘制的默认头像；也可选择本地图片，客户端会
  裁剪为正方形 PNG（最大 512 KB）上传到服务端保存。
- **好友与排行榜**：排行榜按积分降序展示所有已登录玩家的称号与战绩；
  好友窗口支持按昵称搜索玩家。点击排行榜头像可查看对方资料，在他人
  资料中点击「申请加好友」发送申请，对方在「好友」窗口中同意后成为
  好友。自己的资料窗口不显示加好友按钮。

## 棋谱与复盘

- 每局本地、人机或联机对局结束后，客户端把完整着法、双方名称、胜者、
  结束原因与模式写入本地 JSONL：`%LOCALAPPDATA%\Xiangqi\Xiangqi\records\games.jsonl`。
- 默认保留最近 1000 局；超过上限自动重写文件。损坏的行会被跳过。
- 联机对局的完整着法由服务端在 `game_state.moves` 中下发，悔棋后的历史
  以服务端权威快照为准。
- 主菜单「棋谱复盘」按时间倒序列出历史对局，可选择任意一局逐手回放、
  拖动进度条或自动播放；开局即认输的棋谱也能回看。

## 规则说明

坐标约定（源码、协议与测试统一）：

- 棋盘 9 列 × 10 行交叉点；`row` 0..9 自上而下，`row 0` 是黑方底线，
  `row 9` 是红方底线；`col` 0..8 自左向右。
- 河界在第 4/5 行之间；黑方半场 rows 0..4，红方半场 rows 5..9。
- 九宫：黑方 rows 0..2、红方 rows 7..9，列均为 cols 3..5。
- 红方先行；红方前进为 `row - 1`，黑方前进为 `row + 1`。

棋子走法：

| 棋子 | 规则 |
|---|---|
| 将/帅 | 九宫内四方向一步；同列且中间无子时可“飞将”吃对方将/帅 |
| 仕/士 | 九宫内四斜向一步 |
| 相/象 | 田字两步，象眼不得被塞，不得过河 |
| 马 | 日字八方向，马腿不得被蹩 |
| 车 | 四方向滑行，遇子即止，可吃第一个敌子 |
| 炮 | 无炮架时走空位；吃子必须恰隔一个炮架 |
| 兵/卒 | 只能向前一步；过河后可左右一步，永不后退 |

胜负：

- 一方被将军且无合法着法 → **将死**，对方胜；
- 一方未被将军但无合法着法 → **困毙**，同样判负（不是和棋）；
- 任何走法都不得使己方将/帅处于被将军状态（含飞将照面）；
- 0.7.0 暂不裁决长将、重复局面与和棋，相关枚举值已保留。

## 人机 AI

`xiangqi/client/ai_engine.py` 不依赖 Qt，采用扁平 90 格整数棋盘：

- 走法生成与撤销不复制棋盘，增量维护双方将/帅位置；
- 快速将军检测：只反查兵/卒、马、车、炮与飞将；
- alpha-beta 迭代加深 + 吃子静态搜索（含应将）；
- 走法排序：PV、MVV-LVA 吃子、历史启发；
- 评估：子力价值 + 兵过河/马炮占中/车活跃等轻量位置分。

难度配置：

| 难度 | 迭代深度 | 思考上限 | 静态深度 | 说明 |
|---|---|---|---|---|
| 入门 | 1 | 0.25 s | 0 | 在前 4 手中随机选择，棋力较弱 |
| 业余 | 3 | 0.8 s | 2 | 默认难度 |
| 高手 | 4 | 1.5 s | 3 | 更完整的吃子/应将判断 |
| 大师 | 5 | 2.5 s | 4 | 时间允许时完成更深迭代 |

线程与状态：

- `AIWorker(QThread)` 接收不可变棋盘快照、执子方、难度与
  `threading.Event` 取消标记；
- 会话用单调递增的 `request_id` 丢弃悔棋/重开/换先手后的过期结果；
- AI 思考期间可以悔棋，会立即取消搜索并撤回人类上一手；
- 暂停（打开确认框/返回菜单）期间到达的结果先挂起，恢复后再落子；
- 搜索异常时记录错误并自动走出一手合法着法，避免对局卡死。

当前限制：未实现置换表、开局库、残局库与长将/重复局面裁决；AI 为
休闲对弈强度，不代表竞技水平。

## 联机对战

0.7.0 提供账号制联机、排位匹配、个人资料、头像与好友，服务端位于
[server/](server/README.md)：

```powershell
# 终端 1：启动服务端（首次需安装 server 依赖）
py -3 -m venv server\.venv
server\.venv\Scripts\python.exe -m pip install -r server\requirements-dev.txt
python run_server.py        # 前台运行，日志显示在当前终端

# 或者后台运行（不弹出控制台窗口；也可直接双击 start_server.vbs）
python run_server.py --background
python run_server.py --status    # 查看是否在运行
python run_server.py --stop      # 停止后台服务器（或双击 stop_server.vbs）

# 终端 2：客户端
.\.venv\Scripts\python.exe main.py
```

后台模式通过 `pythonw.exe` + 脱离控制台启动，PID 写入
`server/data/server-8765.pid`，日志写入
`server/data/server-8765.out.log` 与 `server-8765.err.log`。

客户端「联机对战」默认连接固定公网入口
`wss://gomoku-host.taild407ad.ts.net:8443/api/v1/ws`（由 Tailscale Funnel
代理本机 8765 端口）。本机离线调试时可在服务器地址栏改回
`ws://127.0.0.1:8765/api/v1/ws`：

1. 首次使用先「注册」：填写昵称与至少 6 位密码；之后用昵称 + 密码
   「登录」。昵称即账号，账号与排位分保存在服务端 SQLite；
2. 登录后由服务端签发令牌；自建房、排位匹配都使用令牌认证，
   服务端以账号身份识别玩家；
3. 点击「自建房」后房主执红；在等待页点「邀请好友」，从好友列表中
   选择一位发送挑战，不再需要房间号；
4. 好友收到挑战弹窗，点击「接受」后执黑进入对局，点击「拒绝」则房主
   可继续邀请其他好友；
5. 所有走子只发送意图，由服务端 `GameModel` 校验并广播完整
   `game_state`；
6. 悔棋需要对手同意；认输立即结束；终局后双方都点「请求再战」才开始
   新一局；断线后保留房间以便同账号重连，双方都离线后房间删除；
7. **排位匹配**：点击大厅第一排的红色「排位匹配」进入队列，服务端优先
   匹配积分相近的等待者；匹配期间可点「取消匹配」退出队列。对局中卡片
   显示双方积分与称号，终局按 Elo 更新并持久化，结果弹窗显示赛后加减分
   与称号变化；
8. **个人资料**：点击头像或「个人信息」打开窗口，可查看/刷新战绩、
   选择默认头像、上传自定义头像。资料与战绩由服务端持久化。
9. **好友与排行榜**：大厅「好友」按钮管理好友列表和申请；「排行榜」
   按积分/称号排序，点击头像查看玩家资料，在他人资料中发送好友申请。
10. **好友私聊**：好友行点「聊天」打开私聊浮层；消息由服务端持久化，
    对方在线时实时推送，离线时下次打开聊天窗补收，好友行显示未读数。
11. **对局聊天**：自建房或排位对局中使用「表情 / 快捷评论 / 文本」发言，
    服务端校验与限流后广播给双方；对话日志可展开，收起时显示未读数。
12. **好友观战**：好友窗口中在线且正在对局的好友会亮起「观战」；点击后
    以只读模式进入该局并实时接收服务端快照。对局结束、房间关闭或点击
    「离开观战」后回到联机大厅。

认证接口：`POST /api/v1/auth/register`、`POST /api/v1/auth/login`。
资料接口：`GET /api/v1/profile`、`POST /api/v1/profile/avatar`、
`POST /api/v1/profile/avatar/upload`、
`GET /api/v1/profile/avatar?nickname=昵称`、
`GET /api/v1/profile/friends`、`POST /api/v1/profile/friends`（申请）、
`POST /api/v1/profile/friends/accept|decline`。
私聊接口：`GET /api/v1/messages?nickname=昵称&limit=50`（历史并标记已读）、
`POST /api/v1/messages?nickname=昵称`（发送）、
`POST /api/v1/messages/read?nickname=昵称`（标记已读）。
好友接口返回 `online`、`game_status`（`playing` / `waiting` / 空）与
`in_game`，用于渲染在线状态和观战按钮。
玩家接口：`GET /api/v1/players`（排行榜）、
`GET /api/v1/players/detail?nickname=昵称`（他人资料）。
协议、消息表与快照字段见 [server/README.md](server/README.md)。
当前限制：房间在内存中；无每步时钟与超时判负。

## 设计约束

1. **单原生窗口**：菜单/对局/联机大厅/复盘都是 `QStackedWidget` 页面；
   所有弹窗是窗口内 `ModalOverlay`，不使用 `QDialog`。
2. **shared 层无 Qt**：规则与模型可被 AI、FastAPI 服务端直接复用；
   测试会扫描 `xiangqi/shared` 的导入。
3. **会话边界**：界面只读不可变 `BoardView`，通过 `GameSession.request_*`
   提交意图；界面不得直接改动 `GameModel`。
4. **选中态只属于界面**：`selected`/`legal_targets` 通过
   `BoardView.with_selection` 叠加，换边/悔棋/重开/终局后清除。
5. **高 DPI**：棋盘静态层按尺寸与 DPR 缓存为 QPixmap；棋子字形按需绘制。
6. **优雅降级**：素材缺失回退纸色背景；音频设备不可用时静音；坏配置
   回退离线默认值，不阻塞启动。

## 联机服务端

`server/` 是可运行的 FastAPI 服务（0.7.0 账号 + 排位 + 个人资料），复用
`xiangqi.shared.rules` / `GameModel` 保证客户端与服务端规则一致：

- SQLite 账号库：昵称唯一、PBKDF2 密码哈希、积分、战绩、连胜、头像与
  好友持久化（旧数据库自动补列）；
- REST 注册/登录签发令牌，WebSocket 首帧令牌认证；
- 内存自建房：创建者执红，可直接邀请在线好友；好友接受挑战即入座；
- 排位队列：按积分相近（±300）优先配对，取消匹配/断线自动出队，
  Elo K=32 且只对排位房间生效；
- 所有联机终局一次性写入双方战绩（普通房间不计积分）；
- 服务器权威走子与完整快照广播，快照携带完整 `moves` 供棋谱复盘；
- 悔棋请求/回应、认输、双方同意的再来一局；
- 断线状态展示与同账号重连；双方离线后房间删除；
- 个人资料 REST：成就派生、默认/自定义头像；
- 好友申请与好友列表：发送、同意/拒绝，双向好友；
- 排行榜：按积分降序返回名次、称号、头像与战绩；公开玩家资料接口；
- 健康检查 `/api/v1/health`，WebSocket `/api/v1/ws`。

尚未实现每步时钟与超时判负。协议细节见
[server/README.md](server/README.md)。
